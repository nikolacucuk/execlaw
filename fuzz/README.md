# Isolated parser and protocol fuzzing

These `cargo-fuzz` targets are intentionally outside the workspace. They use
only generated bytes, temporary directories, and pure parsers; they do not
open network connections, load operator state, or invoke tool dispatch.

Run with a recent nightly toolchain and `cargo install cargo-fuzz`:

```text
cargo fuzz run runner_conversation -- -max_len=65536 -timeout=5
cargo fuzz run server_conversation -- -max_len=65536 -timeout=5
cargo fuzz run registration_handshake -- -max_len=65536 -timeout=5
cargo fuzz run plugin_manifest -- -max_len=262144 -timeout=5
cargo fuzz run plugin_zip -- -max_len=1048576 -timeout=5
cargo fuzz run json_documents -- -max_len=1048576 -timeout=5
```

Keep minimized crashes under `fuzz/corpus/<target>/` and regression-test
each fix in the owning crate. Fuzzing does not claim that external endpoints
or the effects dispatcher are modeled; protocol dispatch authorization stays
covered by server integration tests.
