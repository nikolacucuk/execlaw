# Obsidian LiveSync Publisher

This plugin publishes markdown generated by execlaw into an existing Obsidian
LiveSync CouchDB database. It never reads or writes CouchDB's filesystem data
(`/opt/couchdb/data` or `/mnt/AI_Pool/obsidian_notes`). All CouchDB access uses
its HTTP API.

## Deployment

Build the sidecar on TrueNAS from the repository root:

```bash
sudo docker build -t execlaw/obsidian-livesync-publisher:0.1.0 \
  plugins/obsidian-livesync-publisher/sidecar
```

The manifest mounts the operator path
`/mnt/AI_Pool/obsidian-vault/execlaw` read-only at `/vault/execlaw`.
Install the plugin ZIP through the execlaw admin UI after building the image.

## Configuration

Configure the plugin's admin route with:

```json
{
  "couchdb_url": "http://couchdb-obsidian-livesync:5984",
  "database": "djenka_db",
  "username": "a-dedicated-livesync-user",
  "password": "entered-directly-in-the-admin-form",
  "max_files": 1000,
  "max_bytes": 52428800
}
```

Credentials are stored in execlaw's encrypted per-plugin vault. The GET config
route redacts the password. Use a CouchDB user scoped to `djenka_db`, not the
CouchDB administrator account.

## Compatibility boundary

The publisher writes unencrypted, non-obfuscated ordinary-file metadata and
plain leaf chunks. It is intended for a database configured without LiveSync
E2EE, path obfuscation, or incompatible custom chunk/hash settings. Test with a
new note under `execlaw/` before publishing important data. Publishing is
additive and non-destructive: it does not delete remote files or old chunks.

The first successful publish should make files appear under `execlaw/` in an
Obsidian client connected to the same database. If the client reports a
compatibility mismatch, stop publishing and align its LiveSync compatibility
settings before retrying.
