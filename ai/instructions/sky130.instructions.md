Comprehensive PDK summary from local repo docs:

- Project status and release maturity:
  - The published SKY130 open PDK is documented as experimental preview/alpha.
  - It is suitable for test chips and initial verification, but not positioned as production-ready in that status.
  - The docs route users to known-issues and GitHub issue tracking for current limitations.

- Versioning and traceability:
  - Uses semantic version plus commit trace format: vX.Y.Z-AAA-gHHHHH.
  - Milestone level meanings are explicit:
    - X=0 alpha, X=1 beta, X=2 production-qualified and hardware-verified.

- Process and stack characteristics:
  - SKY130 is described as a mature 130nm-class mixed-signal-capable technology.
  - Documented stack/features include local interconnect + 5 metal layers, 1.8V core domain, 5V IO support, HV devices, optional MiM, and extended options.

- Rules and manufacturability content:
  - Rules are organized by layers, masks, periphery, HV methodology, antenna, RC extraction, device details, and error taxonomy.
  - Assumptions include minimum critical dimensions, latch-up/ESD spacing criteria, and HV/VHV implementation constraints.
  - Antenna methodology is formalized with EGAR/MAX_EGAR relationships and diode bonus handling.

- Library architecture and naming:
  - Library naming is standardized as sky130_<src>_<type>_<name>.
  - Source classes include foundry (fd), efabless (ef), and OSU (osu).
  - Library types include primitive (pr), standard cell (sc), build-space (bd/sp family in naming), and IO/periphery (io).

- Foundry standard-cell families and tradeoffs:
  - Seven families are documented: lp, ls, ms, hs, hd, hdll, hvl.
  - hd and hdll use smaller 9-track class sites; hs/ms/ls/lp share larger compatible footprints; hvl is 5V-oriented with larger footprint.
  - hs/ms/ls are documented as drop-in compatible across equivalent functions/drive strengths.
  - hdll is documented as major leakage reduction versus hd with density/performance tradeoffs.

- Verification and extraction coverage:
  - Verification tree covers DRC, LVS, and PEX paths (with Calibre/Magic/KLayout/netgen references).
  - The docs explicitly note that some design rules cannot be automatically deck-checked and require manual verification.
  - RCX notes include explicit extraction blind spots (for example selected MIM/resistor interactions) that designers must account for.

- Simulation model guidance:
  - Simulation docs identify Spectre models and SPICE/ngspice-compatible models.
  - Device-details pages specify model validity ranges for key FET device classes.

- Current documented gaps/known issues:
  - Multiple documentation sections still contain TODO placeholders.
  - Some flows/files are listed as incomplete for open publication (for example portions of Virtuoso and Calibre collateral in the initial release context).
  - Several libraries or build spaces are documented as placeholders in known-issues context and should be validated before dependency.

Design-use implication for this workspace:

- Treat SKY130 docs as authoritative for topology/rules/library semantics.
- Gate signoff assumptions on explicit verification of tool-deck coverage and known-issue status.
- Prefer conservative library/tool choices (for example sky130_fd_sc_hd unless a different family is justified).

## sky130A vs sky130B (Local Difference)

Based on local nodeinfo metadata:

- sky130A:
  - description includes METAL5, MIM, REDISTRIBUTION options.
  - does not list RERAM in options.

- sky130B:
  - same base stack as sky130A,
  - explicitly adds RERAM option in node options,
  - description includes ReRAM support.

Practical guidance:

- Use sky130A for standard digital runs unless a flow explicitly needs ReRAM-related content.
- Use sky130B only when that additional option is required and validated by your target flow.
